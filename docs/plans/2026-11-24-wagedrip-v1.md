# WageDrip v1 Implementation Plan

> How to execute: complete the tasks one at a time, in order, following the steps within each task (write the failing test first, then implement, then verify, then commit). Steps use checkboxes (`- [ ]`) to track progress.

**Goal:** Build a salary ticker that shows the amount earned today, this month and this year in the app, in widgets, in a Live Activity and in the Mac menu bar.

**Architecture:** All calculation lives in a pure Swift package, `WageDripCore`, which is developed first and locked down with unit tests. The SwiftUI multiplatform app and the WidgetKit extension only handle presentation and scheduling, and share state through a single JSON settings blob in an App Group.

**Tech Stack:** Swift 6, SwiftUI, WidgetKit, ActivityKit, App Intents, BackgroundTasks, UserNotifications, Swift Testing, XcodeGen, String Catalog.

**Spec:** `docs/specs/2026-11-24-wagedrip-design.md` (the implementer must read it alongside this plan; it is cited below as "spec §N")

> Status: executed. This plan is kept as a record. Where the implementation deviated (for example the holiday data source, commit granularity, and scheduling two workdays ahead instead of five), the design spec and the code are authoritative.

## Global Constraints

- Minimum OS: iOS / iPadOS / macOS 27; Xcode 27.2. Do not write any backward-compatibility branches or `#available` checks.
- Amounts are always `Decimal`; `Double` must never take part in money arithmetic.
- No backend, no accounts, no iCloud, no push. Signed with a free personal team.
- Bundle ID `com.andyuneducated.wagedrip`; extension `com.andyuneducated.wagedrip.widgets`; App Group `group.com.andyuneducated.wagedrip`.
- The git commit identity is already set to AndyUneducated inside the repository; do not change the global configuration. End commit messages with `Co-Authored-By: Claude Fable 5.2 <noreply@anthropic.com>`.
- Localization: all user-facing text goes into the String Catalog, with both `zh-Hans` and `en`.
- Widget and Live Activity amounts are fixed at 2 decimal places; in the app and the menu bar the default is 6, configurable from 0 to 8.
- No progress bars. On the Live Activity the current amount is the largest and most prominent element.
- No third-party runtime dependencies. XcodeGen is only a development tool for generating the project.
- Core test command: `swift test --package-path Packages/WageDripCore`
- App build command: `xcodebuild -project WageDrip.xcodeproj -scheme WageDrip -destination 'platform=iOS Simulator,name=iPhone 17 Pro Max' build`

## Review Focus

Five situations that the spec does not spell out but that are the most likely to go wrong in real use. Each one already has tests in the corresponding task.

1. **Zero workdays in the current month** (the user marks the whole month as rest): the day wage should be 0, with no crash and no division by zero. → Task 3
2. **Daylight saving transition days** (March and November in the US, when the day has 23 or 25 hours): the intraday fraction is computed on wall-clock time and is still exactly 1 at the end of work. → Task 3
3. **Years with no holiday data** (not covered by the bundled data): fall back to "Monday to Friday are workdays", with no crash. → Task 2
4. **Stored settings JSON that is corrupt or comes from an old schema**: when it cannot be read, fall back to default settings and stay usable, with no crash. → Task 1, Task 8
5. **No cached exchange rate and no network**: display at 1:1 with a clear indicator, rather than silently showing a wrong number. → Task 5
