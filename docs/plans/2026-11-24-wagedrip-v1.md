# 窝囊费 / WageDrip 第一版实施计划

> 执行方式：按任务顺序逐个完成，每个任务内按步骤进行（先写失败的测试，再实现，再验证，再提交）。步骤用复选框（`- [ ]`）跟踪进度。

**Goal:** 做出一个工资计时器，在 App、小组件、实时活动和 Mac 菜单栏显示今天、本月、今年已赚金额。

**Architecture:** 全部计算放在纯 Swift 包 `WageDripCore`，先行开发并用单元测试锁定。SwiftUI 多平台 App 与 WidgetKit 扩展只做展示和调度，通过 App Group 里的一份 JSON 设置共享状态。

**Tech Stack:** Swift 6、SwiftUI、WidgetKit、ActivityKit、App Intents、BackgroundTasks、UserNotifications、Swift Testing、XcodeGen、String Catalog。

**Spec:** `docs/specs/2026-11-24-wagedrip-design.md`（执行者须同时阅读，下文以"规格 §N"引用）

## Global Constraints

- 最低系统：iOS / iPadOS / macOS 27；Xcode 27.2。不写任何向后兼容分支或 `#available` 检查。
- 金额一律 `Decimal`，禁止 `Double` 参与金额运算。
- 无后端、无账号、无 iCloud、无推送。免费个人团队签名。
- Bundle ID `com.andyuneducated.wagedrip`；扩展 `com.andyuneducated.wagedrip.widgets`；App Group `group.com.andyuneducated.wagedrip`。
- git 提交身份已在仓库内设为 AndyUneducated，不得改全局配置。提交信息末尾加 `Co-Authored-By: Claude Fable 5.2 <noreply@anthropic.com>`。
- 本地化：所有面向用户的文字进 String Catalog，`zh-Hans` 与 `en` 都要有。
- 小组件与实时活动金额固定 2 位小数；App 内与菜单栏默认 6 位，可设 0 到 8。
- 不做进度条。实时活动上当前金额是最大、最靠前的元素。
- 不引入第三方运行时依赖。XcodeGen 只是生成工程的开发工具。
- 核心测试命令：`swift test --package-path Packages/WageDripCore`
- App 构建命令：`xcodebuild -project WageDrip.xcodeproj -scheme WageDrip -destination 'platform=iOS Simulator,name=iPhone 17 Pro Max' build`

## Review Focus

规格没有明说、但真实使用中最可能出问题的五种情况。每条都已在对应任务里加了测试。

1. **当月工作日数为 0**（用户把整月标成休息）：日薪应为 0，不崩溃、不除以零。→ 任务 3
2. **夏令时切换日**（美国 3 月、11 月，当天 23 或 25 小时）：日内比例按墙上时钟计算，下班时刻仍恰好为 1。→ 任务 3
3. **节假日数据缺失的年份**（打包数据没有覆盖到）：退回"周一至周五上班"，不崩溃。→ 任务 2
4. **存储的设置 JSON 损坏或来自旧结构**：读不出来时回到默认设置并保持可用，不崩溃。→ 任务 1、任务 8
5. **没有汇率缓存且没有网络**：按 1:1 显示并给出明确标记，不静默给错数。→ 任务 5

    public init(settings: Settings, rate: Decimal)          // rate：1 薪酬货币 = rate 显示货币
